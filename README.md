# غوار الأصلية — النسخة المحلية 0.2

هذه نسخة تطوير من مشروع ghawar_factory_v01 الأصلي، وليست نظاماً محاسبياً نهائياً معتمداً أو نسخة APK مختبرة.

## التشغيل
1. تثبيت Flutter ثم تنفيذ `flutter create --platforms=android --project-name ghawar_factory_v01 .` من جذر المشروع.
2. حذف الاختبار الافتراضي `test/widget_test.dart` إن أضافه Flutter.
3. تنفيذ `flutter pub get` ثم `flutter analyze --no-fatal-infos` ثم `flutter test test/store_test.dart`.
4. تنفيذ `flutter run` أو بناء APK باستخدام `flutter build apk --release`.
5. على أول تشغيل أنشئ المدير الرئيسي باسم مستخدم وكلمة مرور من ثمانية أحرف على الأقل.

## الوظائف المضافة
- حفظ البيانات في ملف محلي بعد كل عملية، مع استعادة الحالة السابقة إذا فشل الحفظ.
- حسابات المدير الرئيسي والمسؤول والمندوب ونقطة البيع؛ صلاحية منع/قراءة/تعديل لكل قسم؛ تعطيل الحساب وتغيير كلمة المرور.
- كلمات المرور تحفظ مشتقة بـ PBKDF2-HMAC-SHA256 مع ملح عشوائي، وليس كنص صريح.
- المنتجات والمواد الخام والتعبئة والصور والأوزان وسعر البيع والتكلفة ووحدة الصنف.
- الموردون والعملاء وبيانات الاتصال.
- تفاصيل خط الإنتاج: الاسم والقسم والحالة والطاقة والمشرف والآلة والوردية والملاحظات.
- المستودعات والأرصدة الافتتاحية والتحويلات مع منع الرصيد السالب.
- فاتورة مشتريات أو مبيعات لصنف واحد؛ تؤثر في رصيد المستودع وتحتفظ بالمبلغ والتاريخ.
- مكونات وصفة لكل وحدة منتج؛ تنفيذ أمر تصنيع يستهلك المواد ويضيف المنتج دفعة واحدة، مع التراجع عن العملية كلها إذا نقص أحد المكونات.
- المصروفات وإجماليات المبيعات والمشتريات وهامش تقديري حسب تكلفة الصنف المدخلة.
- سجل العمليات، ومنع تعديل الحركات المكتملة عبر الواجهة.

## طريقة الاستخدام
أضف المواد الخام والمنتجات مع الوحدات والتكاليف. أضف الموردين والعملاء. سجّل الرصيد الافتتاحي أو المشتريات. أضف مكونات الوصفة؛ كمية المكون محسوبة لإنتاج وحدة واحدة من المنتج. سجّل أمر التصنيع بالمستودع المصدر للمواد والمستودع المستقبل للمنتجات وخط الإنتاج. ثم سجّل المبيعات أو التحويلات.

لا يوجد تحويل آلي بين وحدات الأكياس والكراتين أو بين الكيلو والجرام. استخدم وحدة واحدة متسقة لكل صنف في المخزون والوصفات.

## حدود هذه النسخة — يلزم إكمالها قبل التشغيل التجاري
- البيانات والحسابات على جهاز واحد فقط. لا توجد مزامنة أو قاعدة بيانات مشتركة بين أجهزة المندوبين ونقاط البيع. الصلاحية تُمنح للقسم كله؛ لا توجد عزل بيانات حسب المندوب أو نقطة البيع.
- لا توجد نسخ احتياطية أو استعادة أو استرجاع كلمة المرور؛ حذف بيانات التطبيق يفقد السجلات. لا تستخدمها كمصدر وحيد لبيانات العمل.
- صور وبيانات التطبيق محلية وغير مشفرة، باستثناء اشتقاق كلمات المرور.
- التصنيع يسجل أمراً مكتملاً فوراً؛ لا توجد دورة اعتماد أو جدولة أو تتبع مراحل أو دفعات/صلاحية أو هدر.
- المحاسبة الحالية إجماليات تشغيلية؛ لا يوجد دفتر أستاذ أو قيد مزدوج أو تحصيل/ذمم أو ضرائب أو فواتير إلكترونية معتمدة أو تقارير مالية نهائية.
- فواتير متعددة البنود، المرتجعات، الإلغاء والتسويات، والبحث والتصدير ما زالت تحتاج تطويراً.
- لم تُشغّل اختبارات Flutter أو تحليل Dart أو بناء APK في بيئة إعداد الملف بسبب عدم توفر SDK. ملف Codemagic يشغّلها قبل البناء. يجب مراجعة نتائجها واختبار التطبيق على جهاز فعلي.

## Codemagic
ارفع محتويات هذا المجلد إلى جذر المستودع: يجب أن تكون lib وpubspec.yaml وcodemagic.yaml في الجذر. اختر workflow android-apk. عند نجاح التحليل والاختبارات والبناء، يظهر app-release.apk في artifacts. توقيع الإصدار هنا هو الافتراضي الذي ينشئه Flutter؛ يلزم إعداد توقيع إنتاج ثابت قبل النشر والمتطلبات الخاصة باسم الحزمة والمتجر.
